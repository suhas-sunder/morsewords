## Release contract

The cumulative W01–W16 branches are review/package history, never future production branches. Retain the frozen audit base `8c83c8214d515565c314ff99bc3df8af88e73121`. At each actual release, fetch current main, verify production, create a fresh `ship/2027-Wxx-theme` candidate from current `origin/main`, then apply only the reviewed increment, amendments and proven prerequisites. Resolve against current emergency fixes, rerun all gates, create an immutable exact-SHA non-production preview, verify hosted SSR/browser behavior, and obtain the owner release decision before any main/production action. Verify the exact production SHA and live smoke afterwards. Never merge an old cumulative stack months later. See the authoritative [release procedure](2027-release-train/README.md), [calendar](2027-release-train/PRODUCTION-CALENDAR.md) and [package manifest](2027-release-train/package-manifest.json). W01 is FOUNDATION / RELEASE INFRASTRUCTURE and W07 is RESEARCH / EVIDENCE CHECKPOINT; neither consumes a standalone user-facing release slot.

Every row below defines a release ID, problem/outcome, exact expected scope, dependency, risk, acceptance and index/approval effect. File paths beginning `components/` and `data/` are relative to `app/client/`; route names refer to `app/routes/`. Names of proposed new modules are implementation targets, not claims that they already exist.

**Common acceptance G:** typecheck; appropriate existing tests plus behavioral regression coverage; build and Netlify production-equivalent SSR; canonical/sitemap/redirect invariants; default smoke. UI changes add functional, visual/content, then regression/accessibility/performance review, with desktop/tablet/390px, light/dark, keyboard and WebKit where relevant. Preserve home visual system, existing controls/storage, canonical engine ranges/presets and segmented export. A test failure stays a failure until investigated; no blanket error suppression. Real ad delivery cannot be forced; distinguish unavailable/blocked and simulated creative evidence.

**Rollback for every week:** revert that week's implementation and release-record commit(s) in reverse order, preserving earlier weeks and user data. Do not restore old Netlify deploys; deploy a reviewed revert through CI. Weeks that migrate storage must retain old reads or provide an explicit reversible migration. Any owner-approved redirect/index proposal must include a URL-level inverse map before release. This common rule applies to each W01–W52 row; week-specific caveats are noted.

**Approval:** ordinary code/copy fixes within the existing product are authorized. Bulk index mutations, new library ingestion, ad lifecycle changes, public rights/license policy changes, external publishing integrations and new data collection require a separate concrete owner decision. “Review” never means an automatic indexing change. Every week below leaves current canonical ownership/indexing unchanged unless its row explicitly proposes an approval-gated change.

## Measurement and decision checkpoints

Weekly operational checks verify production SHA, SSR, links/redirects, input/playback/export completion, assets and console failures. Use no raw messages, answers, worksheets or book selections in telemetry. Every 28 days compare equal windows and separate Google from Bing; record core query groups, query/page breadth, indexation/crawling when accessible, chart image search and aggregate engagement. W08/W16/W24/W32/W40/W48 review cohorts rather than the previous week's rank. W13/W26/W39/W52 include strategic review of actual user value, footprint and unresolved source risks. November update rollout is a confounder, not an attribution shortcut.

## Index-value framework

Keep indexed requires a distinct job, substantive utility, technical health, deliberate internal links and value without Google. Repair retains a valuable task while fixing evidence-backed weaknesses. Consolidate review marks materially interchangeable jobs. Noindex review marks useful functional URLs without a distinct search destination. Remove/redirect review is for obsolete duplicates/aliases. None of these labels executes a mutation. A bulk proposal requires an affected inventory, internal-link analysis, external-link risk, search evidence when available, owner approval and an inverse map. Report unknowns rather than awarding a deceptive aggregate quality score.
