Preserve home visual system, existing controls/storage, canonical engine ranges/presets and segmented export. A test failure stays a failure until investigated; no blanket error suppression. Real ad delivery cannot be forced; distinguish unavailable/blocked and simulated creative evidence.

**Rollback for every week:** revert that week's implementation and release-record commit(s) in reverse order, preserving earlier weeks and user data. Do not restore old Netlify deploys; deploy a reviewed revert through CI. Weeks that migrate storage must retain old reads or provide an explicit reversible migration. Any owner-approved redirect/index proposal must include a URL-level inverse map before release. This common rule applies to each W01–W52 row; week-specific caveats are noted.

**Approval:** ordinary code/copy fixes within the existing product are authorized. Bulk index mutations, new library ingestion, ad lifecycle changes, public rights/license policy changes, external publishing integrations and new data collection require a separate concrete owner decision. “Review” never means an automatic indexing change. Every week below leaves current canonical ownership/indexing unchanged unless its row explicitly proposes an approval-gated change.

## Index-value framework

Keep indexed requires a distinct job, substantive utility, technical health, deliberate internal links and value without Google. Repair retains a valuable task while fixing evidence-backed weaknesses. Consolidate review marks materially interchangeable jobs. Noindex review marks useful functional URLs without a distinct search destination. Remove/redirect review is for obsolete duplicates/aliases. None of these labels executes a mutation. A bulk proposal requires an affected inventory, internal-link analysis, external-link risk, search evidence when available, owner approval and an inverse map. Report unknowns rather than awarding a deceptive aggregate quality score.
