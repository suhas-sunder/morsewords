# W17 — Library detail payload isolation

Branch: `release/2027-W17-library-detail-payload`.
Base: `bc73402dbc2cee734dfb80a0c9cb7405ac0a3f3b`.
Status: VALIDATED review package; not released.

Individual book, audiobook and print clients no longer import the full library
catalog or all-title suitability registry. Loader-only duplicate-title and related
author lookups stay behind `morseBookDetail.server.ts`. Each detail receives one
existing suitability profile and at most four `{slug,title}` related entries.
Canonical eligibility, author matching, ordering, collection context and duplicate
variants are preserved. Lightweight paths and display helpers have separate modules.

The original mixed module remains a compatibility catalog for hub/server callers,
re-exporting canonical runtime helpers. The browser runtime receives its current
summary, retains cache keys/limits and source validation, and fetches only that
book. A matching local source version avoids the old remote public-index requests.
A different deployed source version retains the previous remote export-identity
validation path. Full book text remains on assets.morsewords.com. Loader HTML keeps
only the existing startup excerpt and reviewed summary; no corpus ingestion or
all-book payload fetch occurs at build/request time.

Architecture alternatives reviewed: (1) lazy-loading the old mixed module still
ships the entire catalog during normal interaction; (2) an extra generated related
index adds another freshness artifact; (3) loader projection plus a shared pure
runtime removes the dependency while keeping SSR and the existing directory source.
The third approach was chosen. A first split exposed the remaining 133 KB suitability
registry, so its per-title data was isolated too, with its existing source unchanged.
