## Product and data contract

The existing learning guide offers an explicitly opened, lazily loaded learning-data
panel. The review queue links to it. Nothing is read from a file, downloaded or
written to storage before the corresponding user action. No new indexed route,
account, synchronization service or network upload is introduced.

The version 1 JSON envelope has exactly format, version, includesPrivate and data.
Supported optional sections are bestStreaks (12 explicitly allowlisted registered
keys), reviewQueue, soundFirstProgress and customWords. A missing section or best
key stays unchanged; an explicit null clears that included saved value. No settings,
cookies, ads, book caches, original files, active answers or unfinished sessions.
Counts are integers 0–9999; review data uses the existing 100-target/4000-character
validators and deduplication identity; sound-first uses its canonical set/count
schema. Custom words accept at most 4000 supported Morse-text characters, including
line breaks. HTML, unknown properties/keys/versions, prototype fields, invalid
ranges and malformed JSON are rejected. Text is never evaluated as code or HTML.
The 1 MiB limit is checked against File.size before reading, then against UTF-8
bytes; it supports the complete bounded review queue even with escaped quotes.

Public-only export is the default. Private custom words and targets require an
explicit export opt-in. A private import requires a second explicit opt-in before
restore. Public-only imports retain existing private targets and custom words;
private identity wins a duplicate. If preserved private targets plus incoming
public targets exceed 100, import fails with guidance and removes nothing.

Preview lists current and incoming values/counts without displaying private target
text. Only the listed keys are affected. Unreadable old supported data blocks the
relevant operation rather than silently overwriting it. The guide has no active
score-saving exercise; imported store changes are broadcast to mounted review/path
stores, and navigation rehydrates best scores. Users are asked to close other
practice tabs so older in-flight exercises cannot later overwrite restored progress.

## Recovery and concurrency

Before writing, the panel holds exact old strings/nulls in memory and offers a
validated portable previous-values backup. Backups may contain private text and
are explicitly labeled. Restore verifies that storage still matches the preview;
a changed value requires a fresh preview. Writes are synchronous and bounded;
a partial failure attempts to restore every affected key and reports whether that
recovery succeeded. Failed recovery retains a downloadable backup. Browser storage
is not a cross-tab database transaction; the precondition check plus close-other-tabs
instruction is intentional, not a claim of distributed atomicity.

Undo restores exact prior strings/nulls only if the values still match this restore.
It refuses to erase subsequent progress. Only one recovery snapshot is held at a
time; another import requires explicit dismissal. Leaving/reloading loses in-tab
undo, so a downloadable backup is offered before restore and afterwards.

## Three review passes

Functional coverage includes invalid/oversized files, strict keys/ranges, full-size
queues, partial public/private restores, explicit nulls, deduplication/capacity,
quota/denied storage, stale previews/undo, partial rollback and failed-rollback backup
recovery. Browser downloads are read back and validated. Request inspection checks
that private sentinels, answers and filenames never enter requests.

The visual pass uses the existing home/audio palette, ToolButton, full page width,
readable paragraphs and flat sections. It covers 390/768/1440 widths, both themes
and Chromium/WebKit. The initial WebKit run found focus scheduled before React
committed the preview; focus now follows the commit. Keyboard flow checks preview
focus, restore/undo and beginner exercise results. Scoped Axe checks include the
whole learning-data section. Native file-picker chrome remains browser-owned.

Integration journeys run chooser → first mistake → optional answer comparison →
correct answer → early completion → saved review → export → clear → preview →
restore → reopened review. Listening journeys run chooser → sound-first set →
explicit Chromium playback → static answer/feedback → completion → static weak
review. Windows WebKit uses the equivalent static journey; it is not native audio
proof. Existing native audio and settings suites remain separate gates.
